# KN-91, reading a token's embedding row

`step` in `crates/cpu-decode` starts each token by reading its row of the
embedding table, `hidden` values from `id * hidden`, through `Dense::at`
(binary32, f16 or bfloat16, little-endian) and `round_exact`, which gives the
binary32 of the same value. Every f16 and bfloat16 value is a binary32 value,
so nothing rounds; an exact zero, -0 included, becomes +0. The q, k, v biases
are read the same way.

`Engine.Stage.Embedding::halfRow`, `brainRow` and `singleRow` are that read
for each format, two 16-bit values or one 32-bit value to a little-endian
word. `halfToBinary32` takes the half's fields (KN-58's `exponent` and
`mantissa`) and places the value with KN-62's `Binary32::round`, exactly;
`brainToBinary32` is the bfloat16's bits shifted up 16; `singleToBinary32` is
the word itself. Infinite and NaN values are refused by the Rust; the stage is
stated for finite ones.

## What Lean proves, and what is tested

| Theorem | For |
| --- | --- |
| `embedding_half_is_word` | every half: the binary32 read is at most `0xff800000` |
| `embedding_half_count`, `embedding_brain_count`, `embedding_single_count` | every row: `hidden` values |
| `embedding_row_0` to `_3` | rows evaluated by Lean: f16 (1, -2, the least subnormal, the largest, -0, a fraction, the least normal, the largest subnormal; and a second row at id 1), bfloat16 and binary32 with the same kinds of values |

That the stage equals the Rust is tested on those rows, not proved for every
input.

## The pinned test: `kernel_kn_91`

`kernel_kn_91` pins cpu-decode's embedding lines, reads each row Lean evaluated
through `crates/exact`'s public `Dense::at` and `round_exact`, and requires the
same words.

| Planted defect | Result |
| --- | --- |
| `Dense::at` reading bfloat16 as f16 | rejected: `embedding_row_2`'s largest value read as f16 is not finite (`ScaleNotFinite`) |
| none | passed |
